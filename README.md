# 清审 · 内容预审工作台

为**央媒供稿、新闻报道和政务宣传**设计的本地 AI 预审工具。包含 AI 审稿、AI 审视频、审核记录、问题定位、报告导出。供编辑在报送领导前自查，最终审核由人工完成。

当前版本 **v1.2**：视频增加独立的八维内容审核、整片叙事审读、同期声画联合判断、对照证据和待核实事实分类；原有技术检查继续保留。新功能对新提交的视频生效，历史报告保持原来的检测结果。

## 直接使用

这台电脑已安装依赖和中文语音模型，并配置了 DeepSeek。

1. 双击项目目录中的 **启动清审.cmd**。
2. 浏览器打开 **http://127.0.0.1:8765**。
3. 选择「AI 审稿」或「AI 审视频」，添加待审内容，点击开始预审。
4. 在报告中点击问题定位原文或视频时间点，补充人工复核，导出报告。

启动窗口需要保持运行。按 Ctrl+C 停止服务。服务仅绑定本机地址，适用于一台电脑上的单人工作台。

### 稿件

- 支持粘贴正文、导入 UTF-8 / GB18030 TXT 或 Markdown；正文最多 30,000 字。
- 标题也参与审核。可添加最多 20,000 字参考资料，核对专名、数据、时间与表述。
- 审核日期、隐私信息、格式、错别字、语病、内部逻辑和参考资料差异。
- 每条 AI 文字问题须有可定位的真实原文，无法定位的结果会被剔除并提示。
- 可关闭 AI，仅运行本地规则；报告明确标为审核不完整，不冒充完整语义审核。

### 视频

- 支持 MP4、MOV、MKV、WebM、M4V，单条最多 **512 MB / 30 分钟**。建议 H.264 + AAC MP4，浏览器兼容性最好。
- 本地 Faster Whisper small（CPU / INT8）识别实际口播，保留分段及逐词时间码。
- 本地 RapidOCR 每 1 / 2 / 3 / 5 秒识别画面文字；默认每 2 秒，并补充检测到的镜头中间帧。低置信度文字会明确提示。
- 将临近时间的口播、画面文字、可选 SRT/VTT 字幕及参考稿交给 DeepSeek 比对。
- 视觉检查优先覆盖不同镜头，提供 **24 / 48 / 96 帧**预算，默认 48 帧，每次最多 6 帧。静态重复画面去重；补充镜头代表帧最多 300 个，超过时均匀选取，基础间隔抽帧仍保留。
- FFmpeg 全片检测黑场、长静音、音轨缺失、静止画面及很短的镜头，作为人工复看的候选问题。
- 点击问题、截图或转写文字，可以跳转到视频对应时间。
- SRT/VTT 只是额外比对依据，不替代实际口播转写。

### 视频内容审核（核心）

选择「央媒供稿 / 新闻报道 / 政务宣传」，填写**拟发布标题**及原始采访记录、政策原文或配套稿件。资料建议包含来源与日期；仅粘贴网址不会自动读取网页。

| 内容维度 | 重点疑点举例 |
| --- | --- |
| 事实与数据 | 数量、日期、统计口径互相矛盾；没有依据的因果结论 |
| 报道语境与导向 | 断章取义、以偏概全、污名化或煽情误导；结合引述和新闻语境判断 |
| 政策与规范表述 | 将试点说成全国实施、漏掉适用条件、将拟议措施当成已生效政策 |
| 人物与机构称谓 | 姓名、职务、机构名称、采访身份在口播字幕或资料间不一致 |
| 标题与叙事 | 标题夸大、把计划说成成果、标题与整片内容不符 |
| 声画与字幕一致 | 带时间码的抽帧与同期口播、字幕、配套稿件冲突 |
| 隐私与报道伦理 | 可见个人信息、不当暴露未成年人或受害者、血腥内容呈现、商业植入线索 |
| 素材来源与标注 | 资料画面、示意或 AI 生成标识、水印、地图和授权核查线索 |

短视频整片文字审读一次；长视频先分段，再按时间顺序做一次整片叙事审读。视觉请求同时带上所选画面及各帧前后 4 秒内重叠的口播/OCR/配套字幕，避免只有孤立画面的判断。这里的“联合”使用转写文字与图片，不是原始连续视频/音频模型，也不是深度伪造检测。

结果区分**内部证据冲突 / 与所附资料不一致 / 内容表达风险 / 需外部核实**。文字原句、关联原句及资料引文必须能逐字定位；编造或拼接引文会被排除。全部问题无有效证据时在既有最多三次请求预算内重试，仍失败会标记未完成。资料来自用户，不代表独立核验。

报告首页显示八维检查状态及内容摘要，默认先展示内容疑点，可切到技术检查；点击维度筛选，点击两侧证据回放原片。MD、JSON、CSV 导出包含内容类别、关联证据与资料原文，沿用人工状态及备注。

“已检查所获证据”不表示事实真实、政治或法律合规、播出通过。缺失证据、模型没有回答的维度、未启用的视觉阶段会单独展示。人物身份不从脸部推断，现任职务、政策时效、素材拍摄时地和版权授权需要原始资料。正常批评、引述或争议话题不会因单个词语被机械判错。

### 视频技术与字幕检查（辅助）

| 功能 | 实际检查与证据 | 适用边界 |
| --- | --- | --- |
| 冻结 / 静止画面 | 近乎不变的画面持续超过自设时间，默认 3 秒 | 图卡、照片、片尾定格可能正常 |
| 短镜头 / 闪帧候选 | 镜头变化之间不足 0.35 秒，定位回放 | 闪光和快速剪辑会误触发，不等于画面错误 |
| 响度与峰值 | 测量整片 LUFS、响度范围、真峰值 | 全片数值，不声称定位单个爆音；目标为自设参数 |
| 左右声道 | 两声道 RMS 相差超过 12 dB 时提示 | 分轨混音可能有意如此；只对双声道做左右比较 |
| 字幕安全区 | 底部 OCR 文字框接近边缘，截图叠加框线 | 默认 5% 边距为自查值，不是平台统一标准 |
| 字幕字号 | OCR 文字框高度低于画面高度比例阈值 | 只测可见文字框，不能准确还原字体字号 |
| 字幕可读性 | SRT/VTT 显示时长、字数/秒、时间重叠 | 需要配套字幕文件；不以 OCR 推算精确阅读速度 |
| 音字逐条对照 | 同期口播与字幕文字差异，常见中文数字归一化 | 转写和 OCR 都可能出错，候选差异须试听 |
| 字幕时间偏移 / 漏覆盖 | 相邻口播与配套字幕的时间差、无字幕覆盖的口播段 | 需要 SRT/VTT；不是口型同步检测，也不判断画面一定漏硬字幕 |
| 易错词 | 按用户提供的“错误写法=>正确写法”查找 | 最多 50 条，不自动认定职务或权威写法 |
| 画面比例 | 核对 16:9、9:16、1:1 或不限 | 使用编码尺寸，旋转标记需要结合原片确认 |
| 镜头检查地图 | 标示每个检测镜头是否有画面完成 AI 检查 | 绿色表示至少检查了一帧，不代表全镜头通过 |

字幕对照中的百分比为字符串匹配程度，不是 AI 置信度或正确率。底部文字可能是落款、图卡信息，不能保证全部是对白字幕。词表不自动修改原片。地图出镜、明显水印与隐私线索由视觉模型给出具体复核提醒，不做人物身份推断或授权认证。

使用建议：提供匹配当前成片的 SRT/VTT 和已核实的配套稿件，填写本次重点易错词；在「技术与字幕检查」中按接收方要求设置阈值，完成后逐条回放疑点并记录处理依据。

### 报告与数据

报告包含风险分级、问题证据、修改建议、时间点和实际审核覆盖。支持 Markdown、JSON、问题清单 CSV 下载，以及浏览器打印 / 保存 PDF。视频还可导出实际口播自动转写 SRT，文件名包含 `unverified`，使用前须校对。CSV 已对公式开头的文本作转义，避免表格软件自动执行公式。

每条问题可以记录 **待复核 / 已处理 / 无需处理** 和备注，保存后刷新仍在，并写入导出报告。人工状态不会修改视频，也不会自动改写 AI 的原始预审结论。打印时会自动展示全部问题，避免只打印筛选后的结果。

任务在后台运行；离开当前页面可稍后在「审核记录」查看。可取消任务（正在进行的模型请求可能需等待其结束）。删除任务会删除对应视频和截图，不能恢复。服务意外重启后，未完成任务会标为中断，需要重新提交，不会永久显示处理中。

本地数据保存在 `data/`，密钥保存在 `.env`。二者已加入 `.gitignore`。前端不接收保存的密钥。不要把 `.env` 和 `data/` 上传到公开仓库。已在聊天中明文提供的密钥建议后续更换，并在「模型设置」中更新。

## 为什么使用这个视频方案

视频审核拆成独立的可检查步骤：**实际音轨 → 转写文字；视频画面 → OCR + 视觉抽查；全片 → 技术检测；最后结合参考稿出报告**。任何阶段失败都保留其他阶段的有效结果，明确标出漏查项，不把失败当成没有问题。

语音与 OCR 在本地处理；启用 AI 时，会把待审文字、参考资料及启用视觉抽查后的所选截图发送到 DeepSeek。未启用 AI 时，不会发送这些内容。当前没有联网事实检索，也没有把模型的知识记忆当成权威来源。

**实际边界：**

- 采样和镜头切分会遗漏短暂字幕、快速变化或极小画面；视觉最多按本次预算送检 24 / 48 / 96 帧，不能宣称逐帧检查。精细字幕模式可降低但不能消除遗漏。
- OCR 和语音识别可能弄错人名、地名、数字和方言，冲突提示需要结合原片确认。
- 长视频文字会按约 9,000 字分段，最多 12 个分段内容批次，再做一次整片叙事审读（整片文字预算约 24,000 字）。超过上限均匀抽样并明确说明缺口，保留全部识别文字。短视频只发一次整片文字请求。加上最多 96 帧、每组 6 帧的视觉审核，总共最多 29 个逻辑请求，每个请求最多三次尝试。跨分段或未采样证据的矛盾仍可能遗漏。
- 不自动核定领导现任职务、新闻事实、政策有效性、地图边界、版权或肖像授权；请提供权威材料并人工确认。
- 黑场、静音可能是正常转场或留白，属于技术复核候选，不直接判定为错误。
- 本项目没有经过真实业务语料的大规模准确率评估；测试验证的是功能和已知场景，不代表固定召回率或准确率。

## 参考项目与官方文档

- [SYSTRAN / faster-whisper](https://github.com/SYSTRAN/faster-whisper)：本地转写、时间码和 VAD。
- [RapidAI / RapidOCR](https://github.com/RapidAI/RapidOCR)：使用 ONNX Runtime 的本地中英文 OCR。本项目采用 `rapidocr-onnxruntime` 1.4.4 的稳定接口。
- [FFmpeg 滤镜文档](https://ffmpeg.org/ffmpeg-filters.html)：实际使用 `blackdetect`、`silencedetect`、`freezedetect`、`scdet`、`astats` 和 `ebur128`。
- [PySceneDetect](https://github.com/Breakthrough/PySceneDetect)：参考按内容变化检测镜头、挑选代表画面的思路；当前直接复用已安装的 FFmpeg `scdet`，未增加该依赖。
- [WhisperX](https://github.com/m-bain/whisperX)、[stable-ts](https://github.com/jianfch/stable-ts)：参考带时间码的转写与对齐工作方式；当前复用 faster-whisper 的逐词时间码，并实现本地文字比对，不声称使用这些项目的强制对齐模型。
- [QwenLM / Qwen3-VL](https://github.com/QwenLM/Qwen3-VL)：参考其带时间信息的视频理解与多模态关联思路；本项目未安装 Qwen，实际仍使用现有 DeepSeek 图片接口联合本地转写。
- [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)：结构化报告。
- [DeepSeek 图像理解](https://api-docs.deepseek.com/zh-cn/guides/vision/)：`deepseek-flash` 图片输入。

本项目按上述官方能力实现集成，未复制其他仓库的应用代码。

## 在其他电脑安装

建议 Windows 10/11 x64，Python 3.12 x64，至少 8 GB 内存；16 GB 更适合长视频。首次安装与模型下载需要联网。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe scripts\setup_asr.py
.\.venv\Scripts\python.exe start.py
```

也可双击 `setup.cmd` 安装依赖，再运行「安装语音模型.cmd」。启动后在「模型设置」中输入自己的 DeepSeek Key。默认文字和视觉模型均为 `deepseek-flash`，需有有效余额；「测试连接」只检查认证和模型列表，真正的图片兼容性由画面请求验证。

`requirements-lock.txt` 固定本次实际测试的依赖版本，`requirements.txt` 描述直接依赖兼容范围。项目不需要 Node 构建工具或单独安装 FFmpeg，FFmpeg 可执行文件由 `imageio-ffmpeg` 提供。

## 开发与测试

```powershell
.\.venv\Scripts\python.exe -m pytest -q
node --check static/app.js
node --check static/video-review.js
node --check static/content-review.js
```

自动化测试包含本地规则、AI 原文证据校验、结构化输出损坏、限流重试、取消、标题审核、部分失败、秘密配置隔离、上传校验、导出、重启恢复、真实 FFmpeg 视频解码、黑场/静音与 OCR。

可选在线测试会调用真实 API，产生少量费用，只使用虚构测试内容：

```powershell
.\.venv\Scripts\python.exe scripts\live_smoke.py --review
# test-results/demo.mp4 生成后可运行完整视频测试
.\.venv\Scripts\python.exe scripts\full_smoke.py
.\.venv\Scripts\python.exe scripts\content_smoke.py
```

浏览器回归脚本 `scripts/browser_test.cjs` 使用 Playwright 和本机 Edge，测试上传、文字定位、视频定位、Range 播放请求、报告下载、设置和移动布局。需启动服务并生成完整视频测试记录。先安装 `playwright`，或通过 `NODE_PATH` 指向已有依赖目录。测试截图和结果输出到忽略提交的 `test-results/`。

`scripts/browser_video_extensions.cjs` 验证扩展检查参数、字幕框线、音字对照、人工状态持久化、CSV/SRT 下载和小屏布局。两个浏览器脚本会清理各自创建的测试任务，不删除已有审核记录。

`scripts/browser_content.cjs` 读取完整视频测试记录，验证八维内容报告、内容/技术分类、证据跳转、标题定位、资料引文、导出、小屏布局及模型文本的 HTML 转义。`content_smoke.py` 使用虚构案例测试试点范围、计划/成果和辟谣引述，不能据此推算真实新闻准确率。

## 代码结构

```text
app/config.py    本地配置，不向前端返回密钥
app/schemas.py   输入和 AI 报告校验
app/review.py    DeepSeek、原文证据检查、本地规则
app/content.py   八维内容审读、严格关联证据校验、同期上下文、内容报告
app/media.py     视频探测、FFmpeg、ASR、OCR、抽帧去重
app/quality.py   音频指标、字幕版式与时间对照、易错词
app/exports.py   问题清单 CSV 与转写 SRT
app/jobs.py      有限并发任务、阶段状态与结果汇总
app/store.py     SQLite 持久化
app/main.py      同源 API、上传、报告与媒体流
static/         原生 HTML / CSS / JavaScript，无构建步骤
tests/          单元测试与真实媒体集成测试
scripts/        模型下载与端到端验证
```

后端仅 2 个工作线程，同一时刻最多处理 1 个视频，避免多份模型耗尽内存；语音和 OCR 模型复用。上传分块写盘，视频缩放抽帧，OCR 合并重复文字，视觉去重后限额提交；文字分段不静默截断。SQLite 使用 WAL，接口有大小限制、同源校验和本地主机校验。

当前版本没有多人登录、权限体系、团队审批或云端部署；如果以后要局域网多人使用，应先增加身份验证和文件隔离。
